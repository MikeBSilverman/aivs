# Security requirements

Each row is a security property the system holds today, together with the
tests that prove it. A row lands in the same commit as its test, never
before: a requirement listed without a test reads as enforced and is not
(CLAUDE.md §5, "A flag that is stored and displayed must be enforced").

Every id here is applied as a `requirement` marker on at least one collected
test, and every marker names a row here.
`tests/test_requirements_pinned.py` checks both directions, so deleting or
skipping the last test that pins a row fails the suite. That check is NFR-M3
in [`non-functional-requirements.md`](non-functional-requirements.md).

Ids come from the build plan's security findings and are stable. They are not
contiguous, because a row lands only with its phase. Where a row's full
resolution spans phases, the row states the part that is pinned today and
names the phase that extends it.

| Id | Requirement | Why | Pinned by | Since |

| SF-6 | A submitter cannot claim an ISAC review, and a machine cannot pass as a person. An inbound object whose provenance extension sets `human_reviewed_by_ref` or `reviewed_at` is refused at ingest; validate writes both, from the signed-in editor, on every object. A submission's source is derived from the filing organisation (`system` for automation, whatever the content says), and a consequential change in a `system` submission -- a CVSS or SSVC value lowered against the version members hold, a novel attack vector, a system or parent restart -- is refused at validate unless the editor names it. | A reviewer field in the payload would let content reach a member labelled as human-reviewed when nobody at the ISAC looked at it, and a machine change that lowers a score would pass inside a routine click. | `aivs-schemas/tests/test_extension_2_0.py`, `unit/test_index_columns.py`, `unit/test_provenance_gate.py` | E |
| SF-7 | A contribution about another party's vulnerability is legal by the target's current state: `disclosed_third_party` only once the ISAC's canonical record of it says `published`, `coordinated_disclosure` only with a vendor party an editor placed in the case and that agreed in a distributed opinion, or a VINCE or GOLD EAGLE case on the ISAC's record. Checked at ingest, validate and distribution, so a disclosure withdrawn after validation stops the distribution. | Deciding it from the submitter's bundle would check the rule against the request that asserts it, and a target's state changes after filing. | `unit/test_disclosure_split.py` | E |
| SF-10 | Publication order equals commit order. A second distribution, an early embargo release, and a read that issues a paging cursor each wait for a publication still in flight. | A cursor issued past a batch that commits later skips that batch for good: a warning the member never receives. | `unit/test_publication_lock.py` | A |
| SF-15 | A member learns what happened to its own submission as counts, never as firms. Reach, retrieved, acknowledged and actioned are shown to the submitter alone (anyone else, the ISAC included, gets 404); every count is withheld while fewer than k organisations could see it, and a count is exact only when at least k organisations did the thing and at least k did not (an exact zero, or a count within k of reach, would name firms to a submitter that knows the roster). Reach is only organisations that could retrieve it -- active, a member when it was released, in an active circle with a readable collection -- and a count is only organisations in reach. Firm-by-firm receipts are the ISAC reviewers' only, and a submitter asking for them gets the 404 an absent submission gets. A milestone event fires only once its count is shown exactly, so no milestone is about fewer than k and none stays silent where the count is withheld. | Each receipt is the receiving member's record; a submitter that could list the firms would make the suppression decorative, and a count of one names the reader. | `unit/test_telemetry.py`, `unit/test_admin_and_receipts.py`, `unit/test_policy.py`, `unit/test_portal.py` | E |
| SF-24 | A bundle is accepted whole or not at all. One object that fails validation, including on its discovery scope, refuses every object in the bundle. | A partly stored bundle distributes objects whose context was refused, and the submitter cannot tell which half reached the circle. | `unit/test_disclosure_scopes.py` | D |
| SF-27 | `match[version]=last` resolves the latest version the caller may see, per owner: a reader outside the circle that received the newest version gets the version it may see, not an empty answer. | Resolving globally and then filtering returns nothing for an object whose newest version is withheld, from which the caller infers that it exists. | `unit/test_ownership.py` | E |
| SF-42 | Editorial control is human-only. The ISAC's machine certificate alone neither validates nor enrols, and membership staff never read what members filed. | A machine identity that can distribute is a key whose theft publishes to every member, and the host holds the CA that issues it. | `unit/test_isac_roles.py` | A |
| SF-43 | Circle membership is a set of intervals. A rejoining member reads both of its intervals and nothing distributed in the gap, and intervals cannot overlap, in the fixture schema and in the migrated one. A `joined_at` repair or a backdated re-add never moves an open interval's start earlier for an organisation that has left the circle before, so the gap -- including one a new-interval reconnection withheld -- is never handed over. | A single join time handed a rejoining member everything distributed while it was out. | `unit/test_membership_intervals.py`, `unit/test_quarantine.py`, `migrations/test_migrated_schema.py` | A |
| SF-44 | Naming an anonymous submitter is its own audited editorial action, with a reason, distinct from routine review. | Without it, every ISAC reader saw the identity in an ordinary read, and the anonymity promise depended on nobody looking. | `unit/test_submission_workflow.py` | A |
| SF-46 | Every inbound indicator states when it stops being valid. `valid_until` is required and later than `valid_from`; an indicator naming a network address may be valid for at most 90 days, any other for at most two years; and its `pattern_type` is one a member can run. Excluding expired indicators from packs and readiness extends this in phases E and F. | An indicator with no end is blocked by members for years, long after the address has passed to someone else. | `aivs-schemas/tests/test_extension_2_0.py`, `unit/test_index_columns.py` | E |
| SF-47 | At ingest a third-party contribution is checked only against targets the submitter can see, and a target it cannot see -- or one that is a member's, not the ISAC's -- gets exactly the refusal an absent target does, byte for byte. A vendor's agreeing opinion admits a `coordinated_disclosure` contribution at ingest only if the submitter can read both it and the target's distribution, so an embargoed opinion, or one in a circle the submitter is not in, gets the answer no opinion gets. | Any difference in status or message confirms to an outsider that a pre-CVE finding exists, or that a vendor has agreed before the ISAC released it. | `unit/test_disclosure_split.py` | E |
| SF-48 | Only the organisation that first distributed an object may publish a newer version of it: another organisation's version is refused at validate and at distribution (one validated before the owner distributed is refused at distribution). A `relationship` is owned like anything else: relating two objects is a new id, and needs no exemption. The ISAC and its one automation organisation count as one owner, everywhere ownership is asked (the feed's latest version, the AI gate's previous version, the canonical record). The owner's own newer version supersedes the older in the default feed. | A TIP merges by id and `modified`, so a newer version filed by anyone else rewrites the owner's content for every member -- a vendor marking a member's workaround "not needed", or anyone publishing `revoked: true` under another firm's relationship id. | `unit/test_ownership.py`, `abuse/test_contribution_abuse.py` | E |
| SF-49 | Every distributed object carries its submission's TLP marking in `object_marking_refs`, stamped at distribution, and an object marked with a different TLP is refused. A contribution's TLP is at least as restrictive as every object it references (a sighting's `observed_data_refs` included): against what the submitter can see at ingest, against everything at validate and distribution. | A TIP reads the object's marking, not the submission's column; and a CLEAR opinion on AMBER+STRICT content repeats the content at CLEAR. | `unit/test_markings.py` | E |
| SF-50 | An anonymous submission names its submitter through no structure: a sighting saying where it was seen, or a note or opinion listing authors, is refused at ingest, when anonymity is turned on over stored content, and at distribution. An attributed sighting may name only its filer. | The pipeline rewrites `created_by_ref` and serves everything else verbatim, so structure names the submitter whatever the envelope says; and a sighting placed at another firm states a fact that firm never shared. | `unit/test_structural_anonymity.py` | E |
| SF-61 | A released embargo notifies the circle's current members only, never an organisation that has left. | Notifications were bounded by join time alone, so a former member was told that content it could no longer see existed. | `unit/test_notifications.py` | A |
| SF-63 | Pausing distribution withholds everything not already visible, including an embargo that comes due during the pause, until the pause is released. | The first pause blocked new stamps only; an embargo stamped beforehand still became visible mid-incident. | `unit/test_pause_distribution.py` | A |
| SF-64 | The `isac_analyst` role reads submissions in order to prepare them and holds no editorial verb. | Every ISAC staff member able to push RED is one more person whose compromise publishes it. | `unit/test_isac_roles.py` | A |
| SF-66 | A contribution reaches members without an editor only when a person files it from a member's session (never the ISAC's own organisation or its automation, which file through review, by an allow-list of member types), it carries no prose (a one-click) or its circle is post-moderated (a note, opinion, sighting or RFI grouping), it is about a vulnerability the ISAC's record says is published or a contribution on one (the record as the member sees it, and again as the ISAC does, newer validated or embargoed versions included), it is not RED, it is not a vendor's opinion, and it goes only into circles the member contributes to. Everything else is filed for review. Each organisation may publish at most `contribution_hourly_limit` contributions an hour this way, together with its TAXII inbox posts; past that a one-click is refused, a post-moderated contribution waits for review, and the refusal is audited and raises `contribution_flood`. RED content is never published this way, whatever its referents' TLP. The content rules validation applies run from the ISAC's view; when one refuses, or distribution does, the contribution is filed for review and the member is told one constant reason, never which rule or what it saw; the reason is kept for the ISAC in a `contribution.sent_to_review` audit row, and the log line names only the submission and the kind of refusal. The allowance counts publications by when they were published, under a per-organisation lock. Post-moderation is set per circle by an editor and is off by default. | Unreviewed content is a flood path for a script or a stolen certificate, and the lane rule is what keeps prose, pre-CVE content, RED and a vendor arguing about its product in front of an editor. | `unit/test_one_click.py`, `unit/test_post_moderation.py`, `abuse/test_sharing_abuse.py` | E |
| SF-68 | An editor may file for an active member organisation only with the SHA-256 of a consent artefact, which is stored with the filing alongside the editor who filed it. The member is sent a contentless "filed on your behalf" event at once, and the filing is listed on its portal dashboard, which needs no webhook. The filing is anonymous by default, and it cannot be distributed until the member confirms it or 24 hours pass; only a person at the member may confirm, never its machine certificate, and it can withdraw the filing as it would its own. | Without a consent artefact and a window, an analyst can attribute content to a member that never sent it, and the member learns of it only once every other member has. A member with no webhook subscribed to the event was never told; a collector that confirmed what arrived would close the window unread. | `unit/test_proxy_filing.py`, `abuse/test_sharing_abuse.py` | E |
| SF-69 | A TAXII POST to a collection is accepted only from a contributor to its circle (a reader gets 403, anyone else the 404 an absent collection gets). Each POST becomes one `submitted` submission with source `system`, which is never published without review, is anonymous, has the circle's TLP floor and scope `disclosed_third_party` (so the disclosure split applies), and refuses `vulnerability` and `identity` objects. Each POST counts against the hourly allowance of SF-66. Its status resource is readable by the posting organisation alone. | The inbox is a machine write path into the review queue: a member's platform must not be able to publish, attribute, or fill the queue unseen. | `unit/test_taxii_inbox.py`, `abuse/test_sharing_abuse.py` | E |
| SF-70 | A posture -- a member's VEX status on a vulnerability and whether it deployed a detection -- is read and written by its own organisation only, and anyone else, the ISAC included, gets the 404 an absent row gets. It defaults to `under_investigation`. The ISAC's reviewers see counts per status, each exact only when at least k members have that status and at least k of those with a posture do not (so no exact zero, and no count equal to the total), all of them withheld below k in total, and the total withheld whenever a count is; only active members are counted, never the ISAC or its automation, and only for a vulnerability that was distributed. The audit row records that a posture was set, never which, and no member's posture request names the vulnerability in its URI: it is written with the id in the body and listed at `/api/v1/postures`. Two first writes make one row. | "Affected", held per firm by the ISAC, is the list a G-SIB's counsel will not allow to exist; the audit log names which firms recorded a posture, so "6 of 6 affected", or a zero beside the total, states each one's status; a total beside a withheld count gives the withheld one away by subtraction; the ISAC's own row counted toward k lets five rows describe four firms; and a request line is logged beside the client's identity and forwarded off the platform, so "firm X set a posture on V at t", read beside the summary before and after, is the status. | `unit/test_posture.py` | E |
| SF-71 | The committed proxy configuration puts the hybrid post-quantum group `X25519MLKEM768` alone in its first tuple, so the server prefers it even over a classical key share the client sent first, with a classical fallback in a later tuple; and the default proxy image is built on an OpenSSL that implements ML-KEM. Against the running proxy, the opt-in end-to-end tier (`e2e/test_pqc.py`) shows an OpenSSL 3.5 client negotiating `X25519MLKEM768` in both orders and a classical-only client connecting with `X25519`; it is not counted as a pin, because the ordinary run skips it. | TLS traffic carrying embargoed intelligence, recorded today, is readable once a quantum adversary exists; key exchange is the part that cannot be fixed retroactively. | `unit/test_proxy_config.py` | A |
| SF-73 | Each TOTP code signs an operator in once (RFC 6238 section 5.2): a code for the time step last accepted, or an earlier one, is refused and counts towards the lockout, and two concurrent sign-ins with one code let exactly one in. | The same code signed in any number of times inside its 90-second window, so a code read over a shoulder or captured by a phishing page could be replayed while it lasted. | `unit/test_sessions.py` | D |
